# rtaime Product Identity

## Canonical brand

The canonical product name is:

**rtaime**

It is written in lowercase in product prose, documentation and user-facing branding.

## Pronunciation

**rtaime** is spoken as:

**realtime**

The pronunciation deliberately reads like the real-time production domain the platform targets.

## Name expansion

**rtaime** expands to:

**Real Time AI Media Engine**

The name combines the product's primary concepts:

- **Real Time** — deterministic, production-oriented media execution.
- **AI** — governed inference integrated into the media pipeline.
- **Media** — video, audio, graphics and production assets.
- **Engine** — the runtime, control and processing foundation behind the operator experience.

## Slogan

The canonical slogan is:

> **Production-grade real-time AI media platform.**

Use this wording verbatim in primary product positioning unless a document has a specific technical reason to omit marketing language.

## Product category

Primary category:

**Real-time AI media platform**

Useful secondary descriptions:

- production media platform
- real-time production engine
- software-defined media-server platform
- governed AI media runtime

Use **media server** when category recognition helps the audience understand the product, but do not position rtaime as playback-only infrastructure.

## Positioning

Canonical positioning statement:

> **rtaime is a production-control-first real-time media platform that combines deterministic execution, operator trust and governed AI without giving AI authority over Program.**

Short product description:

> **rtaime unifies video, audio, graphics, recording, outputs and governed AI in a production-shaped real-time system with explicit authority, visible health and bounded recovery.**

## Message hierarchy

Use this order when introducing the product:

1. **rtaime**
2. **Production-grade real-time AI media platform.**
3. **Real Time AI Media Engine**
4. the audience-specific value proposition
5. concrete proof from implemented or qualified product behavior

Do not lead with the acronym expansion when a short marketing surface needs a stronger product message. The expansion remains canonical supporting identity.

## Core message pillars

### Trust the Program

Production authority is explicit. Runtime execution and recovery are designed around controlled state rather than optimistic UI behavior.

### Operate the whole media path

Media, timing, Preview/Program, graphics, audio, recording, output and health belong to one operator model.

### AI without surrendering control

AI is governed, bounded and optional to continuity. It does not own Program state.

### Operational trust is a feature

Ready, degraded, recovering, unavailable and unverified states should be visible rather than inferred.

## Brand voice

rtaime communication should be:

- precise;
- technically credible;
- confident;
- evidence-bound;
- production-focused;
- understandable to both operators and engineers.

Prefer concrete language such as deterministic, governed, authoritative, observable, bounded, resilient, qualified, real-time and production.

Avoid unsupported language such as zero-latency, flawless, unlimited, fully autonomous or certified unless evidence explicitly supports the claim.

## Naming rules

Use **rtaime** for the brand and product name.

Existing technical identifiers may retain established casing when changing them would break compatibility or conventions, for example:

- environment variables such as RTAIME_CONTROL_ENDPOINT;
- project and assembly names such as rtaime.RuntimeHost;
- schema fields or externally visible identifiers already defined by contracts.

Do not reinterpret the acronym differently in separate documents. The canonical expansion remains **Real Time AI Media Engine**.

## Showcase terminology

External presentation language should use:

**rtaime Product Showcase**

Established internal scripts and filenames may retain terms such as InvestorDemo where changing them would create unnecessary compatibility or qualification churn.

Avoid **funding prototype** or **funding demo** in new customer-facing copy.

## Claim discipline

Marketing language must preserve the repository evidence model.

Implemented software behavior may be described directly.

Qualification-sensitive terms such as **STABLE**, **VALIDATED**, **CERTIFIED**, physical hardware performance, device compatibility and reference-platform readiness may be used only when supported by the corresponding release or qualification evidence.

**UNVERIFIED** remains materially different from **PASS**.
